# Evaluation contract

Engine speed, task quality and authorization safety are separate results.
No app model is marked task-validated by a speed test.

## Reproduce the CPU smoke comparison

On macOS, with an existing SmolLM2-360M-Instruct Q8_0 GGUF and llama-server:

```sh
python3 eval/compare.py --model /path/smollm2-360m-instruct-q8_0.gguf \
  --llama-server /path/llama-server --threads 2 --repeats 3 \
  --output build/evidence/unique-run.json
python3 tests/app/eval_test.py
```

The runner launches engines serially, verifies identical input token IDs and
uses the same GGUF hash, 4096-token context, CPU, f32 KV, greedy sampling,
seed and 16-token ceiling. llama.cpp receives `cache_prompt: true` and a fixed
slot. Do not replace this baseline with stateless HTTP. The binary hashes,
source state, commands and raw responses are retained. Output paths cannot
be overwritten; failed runs preserve an error rather than becoming successes.

Record startup separately from first inference and warm requests. Process
startup is not disk-cold: the operating system's file cache is not flushed.
RSS is sampled at request boundaries; it is not a peak-memory measurement.
Energy remains null without a reproducible external measurement. An optimized
Metal baseline belongs in a separately labeled product comparison.

## First observed smoke result, 25 September 2026

Apple M1 Max, macOS, SmolLM2 Q8_0, two CPU threads, one short English request,
three warm repetitions. Both engines answered Paris and generated two tokens.

| Engine | First inference | Median warm request |
| --- | ---: | ---: |
| geistd | 2418 ms | 2078 ms |
| llama.cpp build 10621, c1d0e7a00 | 726 ms | 58 ms |

**This run does not demonstrate a speed advantage for geistd.** Its current
prefill implementation resets when the requested context diverges from the
history after generation; it reused zero tokens here. llama.cpp retained 20
of the 21 prompt tokens. Resident sessions alone are not an advantage over a
baseline that already caches prompts. These are narrow smoke measurements,
not a ranking across models, hardware or workloads.

Source: [unaltered raw run](../benchmarks/2026-09-25-mac-cpu-smoke.json), copied from `build/evidence/mac-cpu-comparison-01.json` generated by the runner.
Keep this raw file alongside the validation bundle. The engine library was
pinned to `25861c0bd197f1a98f17e49efe0cdc48a0e40713`; the app/daemon changes
were an uncommitted development build identified by its recorded binary hash.

## Task packages

`tasks/catalog.json` versions the prompt instruction, input/output budget,
example and quality status. Rewriting, summarization and ideas are unverified
experiments. Correctness needs a held-out corpus and human review criteria;
non-empty text, token speed or one attractive example cannot establish it.

Home Assistant uses the existing geistagent corpus and scorer, not a second
policy implementation in this repository:

- [geistagent evaluation](https://github.com/geisten/geistagent/tree/main/eval)
- [HA grounded quality, #15](https://github.com/geisten/geist-home-assistant/issues/15)
- [HA Pi latency/RSS and product comparison, #16](https://github.com/geisten/geist-home-assistant/issues/16)

The remote-agent smoke exercised two existing shipped-tool cases with BitNet.
Both tool and argument choices matched; no decline probes were included, so
the original scorer correctly reports `shippable: false`. Do not turn this
adapter check into a product-quality or safety claim. Measure full DE/EN,
unknown/ambiguous requests and exposure violations before enabling actions.
